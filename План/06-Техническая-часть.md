# Техническая часть

## Согласованные требования

- React.
- Установка веб-приложения на телефон как PWA.
- Дневник и настройки хранятся в localStorage браузера на одном устройстве.
- Синхронизация между устройствами и серверное хранение не требуются.
- После закрытия приложения данные должны сохраняться.
- Целевая платформа - Android: Google Chrome и установленная PWA. Отдельная сложная адаптация под множество платформ не требуется.
- Дата рождения сохраняется один раз; возраст рассчитывается автоматически.
- В первую итерацию входят копирование дневника текстом и отдельная страница норм. Автоматическое сравнение с нормами, экспорт, импорт и полный прогноз не входят.

Предлагается обеспечить работу установленного приложения без интернета после первого успешного открытия и загрузки необходимых файлов.

Согласованный стек: React + TypeScript, Vite, CSS Modules, React Router, Zustand с persist для общего состояния и localStorage, vite-plugin-pwa и Vitest. Zustand заменяет ранее предложенные useReducer + Context; второй параллельный механизм общего состояния не нужен.

## Предлагаемое разделение кода

1. Экраны и формы: дневной учет, заполнение ночи, настройки, просмотр дней.
2. Расчеты: длительности, суммы, ближайшее засыпание, проверка пересечений.
3. Сохранение и загрузка локальных данных.
4. Расчет возраста по дате рождения и отдельная страница возрастного справочника.
5. PWA: манифест, иконки и кэширование приложения.

Расчеты времени должны быть отделены от отображения, чтобы их можно было проверить на конкретных примерах.

## Предлагаемая структура данных

| Сущность | Основные сведения |
| --- | --- |
| Настройки | Дата рождения ребенка и последнее подтвержденное плановое ВБ |
| День | Идентификатор, дата, события, общее примечание, состояние заполнения |
| Дневное событие | Идентификатор, тип (подъем, дневное засыпание, пробуждение, «уснул на ночь»), фактическая дата и время, комментарий |
| План ВБ | Привязка к пробуждению и введенная длительность |
| Ночь | Идентификатор, связь с днем, интервалы, черновик или завершенная запись |
| Ночной интервал | Идентификатор, начало, конец, комментарий |
| Документ хранения | Версия формата и сохраненные сущности |

Плановое ВБ хранится отдельно от фактического времени засыпания. Рассчитанные суммы предпочтительно получать из событий, чтобы после исправления времени не оставались устаревшие итоги.

Утренний подъем и последнее ночное пробуждение могут обозначать одно событие в жизни ребенка. Необходимо связать их или проверять согласованность, не создавая двойной учет.

## Работа со временем

- Сохранять полную дату и время события, а не только строку «03:15».
- Хранить плановые длительности в минутах.
- Для интерфейса форматировать время в часы и минуты.
- Отсчет текущего интервала получать из сохраненного времени начала и текущего времени.
- Не накапливать длительность только за счет работы таймера: браузер может приостановить вкладку или приложение может быть закрыто.
- После возврата в приложение заново вычислять прошедшее время.
- При ручном вводе ночи учитывать календарные даты, переход через полночь и последовательность интервалов.
- Дневной учет идет от утреннего подъема до события «Уснул на ночь».
- Суточный период идет от утреннего подъема до следующего утреннего подъема, даже если длится не ровно 24 часа.
- Считать возраст по календарной дате рождения, не заменяя месяц четырьмя неделями. Возраст на прошлую дату при необходимости выводить на дату записи.
- Хранить дату рождения как календарную дату; не допускать ее смещения из-за часового пояса или ввода будущей даты.

## Правила расчетов

`Ближайшее засыпание = фактическое пробуждение + плановое ВБ`.

`Длительность завершенного сна = фактическое пробуждение - фактическое засыпание`.

`Текущий сон = текущее время - начало незавершенного сна`.

`Фактическое ВБ = фактическое засыпание - предыдущее фактическое пробуждение`.

`СДС = сумма длительностей дневных снов выбранного дня`.

`Ночной сон = сумма заполненных непересекающихся интервалов ночного сна`.

`Бодрствование между ночными снами = сумма промежутков между соседними интервалами`.

`Суточный объем сна = СДС + фактический НС в периоде от подъема до следующего подъема`.

Попытки уложить, кормления и другие события в комментариях не преобразуются в интервалы автоматически.

Незавершенный день или незаполненная ночь дают предварительный, а не окончательный суточный итог. Подсветка соответствия нормам и вычисление отклонений в первой итерации не реализуются.

Для копирования дневника формировать обычный текст из сохраненных событий, комментариев и расчетных итогов выбранного периода. Предлагать последнее ВБ как редактируемое значение с подтверждением для текущего отрезка.

## Сохранение

Предлагается:

- Сохранять событие сразу после подтверждения, без отдельной общей кнопки сохранения дня.
- Сохранять черновик ночной формы и заметки при редактировании.
- Использовать версию формата, чтобы последующие обновления могли читать уже записанные данные.
- При ошибке чтения или записи показывать понятное сообщение; не подменять существующий дневник пустым и не стирать его молча.
- Проверять данные после загрузки перед расчетами.

Данные localStorage привязаны к браузерному хранилищу и адресу приложения. Очистка этого хранилища удаляет дневник. Экспорт, импорт и отдельная функция резервного копирования в первую итерацию не входят.

## PWA

Предусмотреть манифест, название, иконки, удобное открытие на отдельном экране и кэширование необходимых статических файлов.

Способ установки и поведение проверить в Chrome на Android и в установленной PWA. Широкая матрица браузеров и отдельная поддержка других мобильных платформ в первой итерации не требуются.

Пользователь согласовал публикацию на бесплатном Vercel Hobby и хранение кода в GitHub-репозитории `vadicusrad/sleep-app`. Основная ветка — `main`. Подготовлена конфигурация Vercel для Vite, прямых ссылок на страницы и обновления PWA. Записи дневника остаются на устройстве.
